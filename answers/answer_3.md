### Answer 3

The code coverage should be less than 100%, indicating that some lines of code are not run in the tests. These lines are the ones in the preamble of the function, which check that user input is as expected. This makes sense: in our tests we never run "error" cases which trigger these checks, and so we never take both outcomes of these conditional (i.e. "if-") statements. To increase code coverage, you should write "misuse" tests to make sure that the function errors when expected, i.e. trigger these errors (see accompanying solution code). While writing these extra tests to get to full coverage, you should find a previously unnoticed bug in the function: the case of "wrong ploidy" is badly implemented. You should fix that line of code so the tests pass and the code coverage is full.
